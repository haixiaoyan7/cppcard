# C++ 面试总结 · 方案 B《一个对象的一生》编排

> 核心思路：不按知识分类，而按「一个对象从生到死」的生命弧线来串。
> 贯穿对象是一条 `LogMessage`：**诞生 → 有了身份 → 被复制转移 → 进容器 → 被泛化 → 被函数式操作 → 被并发访问 → 死亡**。
> 正常死亡散落在幕 1–4；幕 8 收**异常中途的死亡**（023）和**该死没死**（006）。幕 4 扩容要用的 `noexcept` 回指 023。
> 走完这条线，整个 C++ 语言层面就讲透了；篇二、篇三把同一条日志拉远，看成指令、进程、网络和存储；终章把它装回一台能跑的机器。
> 原卡号（001–086）保留作标注，方便回查对应卡片。

## 篇一《一个对象的一生》— 语言核心（54 题）

一条完整的生命弧线：`LogMessage` 被造出来，有了多态身份，被复制/移动，被放进缓冲容器，
被模板泛化成任意类型，被 lambda/function 操作，被线程池同时访问，最后**死亡**——
栈帧结束自动析构、堆上 RAII/智能指针释放、移动后空壳仍要析构、容器搬迁时批量销毁。
幕 8 收束**异常中途的死亡**与**泄漏**。

## 核心亮点：把「对象的一生」讲成一个完整故事

篇一用一条 `LogMessage` 的生命弧线，把原本割裂在多个 topic 的题目缝合成连贯叙事：

| 生命阶段 | 幕 | 来自原 topic | 缝合逻辑 |
|---------|----|-----------|---------|
| 诞生 | 幕 1 | 01 内存 | 住哪、怎么造、谁拥有 |
| 有身份 | 幕 2 | 02 OOP + 07 底层(058) + 018/019 | vtable 和对象布局并排；转换体系收到 015 和 019 |
| 被复制转移 | 幕 3 | 02 + 03 | 深浅拷贝与移动语义合流；扩容用的 `noexcept` 回指幕 8 |
| **进容器** | **幕 4** | **05 STL** | **容器要求元素可移动，承接幕 3；含迭代器与 allocator** |
| 被泛化 | 幕 5 | 04 模板 + 03(concepts) | 推导紧跟实例化，constexpr 接元编程 |
| 被操作 | 幕 6 | 03 现代 | lambda/function；variant 对照幕 2 虚函数 |
| **被并发访问** | **幕 7** | **06 并发 + 03(031)** | **多线程共享 + 任务/协程异步** |
| **死亡** | **幕 8** | **03(023) + 01(006)** | **正常死亡散落幕 1–4；此处收异常死亡与泄漏** |

021 不拆卡：`std::move` 在幕 3 讲完再进容器；`std::forward` 在幕 5 的 035 之后回看。
